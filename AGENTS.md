# AGENTS.md

Пиши лаконично, коротко, по делу: объясняй все термины простыми словами (как ребёнку) и показывай причинно-следственные связи — почему так, а не иначе.

## Процесс выполнения задачи (для агента-испытуемого)

Тебе дают задачу вида «выполни C2 из tasks/coding/kotlin». Порядок строго такой:

1. **Прочитай спеку** задачи: `tasks/<категория>/<язык>/<задача>.md`.
2. **Создай ветку** в проекте из `source/` (например `source/nicehash`):
   `task/<номер-задачи>` (например `task/c2`). Вся работа — только в ней.
3. **Выполни задачу** по спеке. Следуй ограничениям спеки и паттернам проекта.
4. **Проверь себя видимыми проверками:** `./gradlew test` и
   `./gradlew assembleDebug` должны быть зелёными. Чини, пока не зелёные.
5. **Закоммить** результат в свою ветку.
6. **Напиши отчёт** в `runs/<дата>/<модель>/<задача>-<попытка>.md` и `.json`:
   что сделано, какие тесты добавлены/пройдены, что не получилось и почему,
   число изменённых файлов/строк. JSON — по схеме из MANIFEST.md.
7. **Ничего не удаляй** — ветку и рабочую копию убирает экзаменатор после оценки.

## Запреты (нарушение = дисквалификация)

- **НЕ читать `checks/`** — это скрытый ответник экзаменатора. Чтение
  фиксируется в логах сессии и означает провал прогона.
- НЕ менять спеки задач, MANIFEST.md, AGENTS.md, чужие ветки и отчёты.
- НЕ удалять/ослаблять существующие тесты ради зелёного прогона.
- НЕ подгонять код под увиденные проверки — пиши по спеке.

Скрытые проверки экзаменатор накладывает на твою ветку ПОСЛЕ прогона.
Твоя задача — честный результат по спеке, а не угадывание ответника.
