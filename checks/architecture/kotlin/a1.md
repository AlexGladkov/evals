# СКРЫТЫЕ ПРОВЕРКИ — A1 (моделям НЕ давать)

Модернизация одного экрана: Moxy→ViewModel, XML→Compose. Поведение — fidelity.

## Поведенческие тесты (JVM)

Эталон: поведение IncomePresenter базового снапшота на фейковых зависимостях
(фейковый MoneyRepository + фейковый ExchangeServer), зафиксировать ДО прогонов.

| Кейс | Ожидание |
|------|----------|
| Успех | состояние содержит Income с конвертированными значениями (monthValue/weekValue/dayValue/hourValue), usdRate, currencyRate — числа совпадают с эталоном |
| Ошибка репозитория | состояние ошибки, не краш |
| Смена валюты | пересчёт как в оригинале |
| Загрузка | состояние загрузки присутствует |

ViewModel тестируется напрямую (в этом смысл миграции): fake-зависимости,
TestDispatcher для корутин / InstantTaskExecutorRule для LiveData.

## Механические проверки

- IncomeViewModel существует (androidx.lifecycle.ViewModel).
- Экран рендерится через Compose (setContent/ComposeView), fragment_income.xml
  больше не используется экраном (удалён или отвязан).
- Moxy-импорты/аннотации в файлах экрана Income отсутствуют.
- DI обновлён, экран достижим из навигации (вход не потерян).
- Остальные экраны не тронуты (дифф вне Income-экрана минимален).
- Есть JVM-тесты ViewModel.

## Гейт

- `./gradlew test` зелёный; `assembleDebug` собирается.
- Поведенческая эквивалентность с эталоном (допуск 1e-9).

## Штрафы / незачёт

- Поведение изменено (другие конвертации, потерянные состояния/элементы) — незачёт.
- «Починенные» баги оригинала — штраф fidelity.
- Задеты другие экраны — штраф за дифф.
- Данные захардкожены в UI вместо получения из репозитория — незачёт.
- Compose «для галочки» (экран фактически на XML) — незачёт.
- Визуальная деградация (потеряны элементы: выбор валюты, курсы, периоды) —
  штраф по рубрике (проверяется ревью/эмулятор-бонусом).

## Бонус

- UI-smoke на эмуляторе (скриншот до/после) — не гейт, плюс к качеству.
