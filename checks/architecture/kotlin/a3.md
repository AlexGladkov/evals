# СКРЫТЫЕ ПРОВЕРКИ — A3 (моделям НЕ давать)

Структуру НЕ предписываем — проверяем правила. Любая структура, удовлетворяющая
правилам, = зачёт. Это тест понимания границ, а не угадывания нашей схемы.

## Механические проверки (парсинг Gradle + grep)

| # | Проверка | Как |
|---|----------|-----|
| 1 | ≥3 модуля (без benchmarks) | settings.gradle include |
| 2 | Чистый домен: модуль с моделями+интерфейсами репозиториев | размещение файлов |
| 3 | Домен без Android | build.gradle: нет com.android.* плагинов, androidx/android.* зависимостей; grep android.* импортов = 0 |
| 4 | Домен не зависит от модулей проекта | граф: исходящие рёбра домена = 0 (project-зависимости) |
| 5 | Граф ацикличен | обход графа project(...) зависимостей |
| 6 | data не зависит от UI-модуля | граф |
| 7 | Размещение по границам | реализации/провайдеры/Room/конвертеры в data; презентеры/activities/fragments в UI; модели/интерфейсы в домене |
| 8 | DI/Room/kapt работают | assembleDebug собирается (Dagger-граф через модули) |
| 9 | Тесты перенесены и зелёные | ./gradlew test |
| 10 | Отчёт: схема + обоснование | runs/ отчёт прогона |

## Поведенческая fidelity (гейт)

- Golden расчёта дохода: эталон базового снапшота на фейковых данных,
  допуск 1e-9 (баги сохраняются).
- Экраны/навигация на месте (механически: activities/fragments не удалены).

## Метрика

- **module_score** = выполненные проверки 1–10 / 10 (частичный зачёт).
- Гейт: assembleDebug + test + golden. Не собирается — module_score capped
  (черновик: максимум 0.4, веса зафиксировать до прогонов).

## Штрафы / незачёт

- Цикл в графе — незачёт (главная архитектурная ошибка).
- Android в домене — крупный штраф.
- Формальное разбиение (новый модуль-пустышка, всё осталось в :app) — незачёт.
- Удаление кода/экранов ради сборки — незачёт.
- Поведение изменено — незачёт gate.
- Нет отчёта с обоснованием — проверки 10 = 0, штраф к качеству
  (архитектор обязан объяснять решения).
- Задеты benchmark-модули — штраф.

## Рубрика качества

- Обоснование границ внятное (почему домен чистый, почему data не знает UI) —
  плюс; «просто разбил по папкам» без понимания — минус.
- Осмысленное дополнительное выделение (:core:network, :core:common и т.п.)
  с обоснованием — бонус, если граф правильный.
- Минимальность диффа: переносы, а не переписывание кода.
