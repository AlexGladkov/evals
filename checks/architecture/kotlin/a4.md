# СКРЫТЫЕ ПРОВЕРКИ — A4 (моделям НЕ давать)

Сквозная фича: проверяем глобальность интеграции, скоупы, нетронутость экранов.

## Механические проверки

| # | Проверка | Как |
|---|----------|-----|
| 1 | Экраны/презентеры не изменены | дифф: существующие presenters/fragments без правок; допустимы минимальные правки корневых точек (application/base-activity/root-контейнер) |
| 2 | Интеграция на корне, не копипаста | один механизм интеграции; одинаковые блоки чата, размноженные по активити/фрагментам, = провал |
| 3 | Покрытие всех экранов | механизм application-level или базовый: чат доступен и на вторичных активити (Choose/Add/Detail), не только MainActivity |
| 4 | Состояние app-scoped через DI | singleton/компонент приложения в DI-графе; не object-глобал мимо DI |
| 5 | Доменная модель + репозиторий по паттерну | сообщение в domain, провайдер/Retrofit/конвертер по образцу проекта |
| 6 | Оверлей: кнопка + окно чата | layout/compose-компоненты существуют, подключены к корню |
| 7 | Отчёт с обоснованием | runs/ отчёт: механизм, скоуп, покрытие |

## Поведенческие тесты (JVM + MockWebServer)

| Кейс | Ожидание |
|------|----------|
| Отправка сообщения | POST по контракту, reply добавлен в историю |
| HTTP 500 / таймаут | состояние ошибки в чате, приложение не крашится |
| Битый JSON | ошибка, не краш |
| Навигация (смена экрана) | история и открыт/закрыт сохраняются (тест на state-holder вне экранов) |
| Закрытие/открытие оверлея | история сохраняется |
| Пустая история | корректное пустое состояние |

## Гейт

- `./gradlew test` зелёный; `assembleDebug` собирается.
- Fidelity: golden расчёта дохода + существующие экраны работают как раньше.

## Метрика

- **global_score** = выполненные проверки 1–7 / 7 + поведенческие кейсы
  (веса зафиксировать до прогонов; черновик: механика 50%, поведение 50%).
- Частичный зачёт: чат только на главном экране = максимум 0.5 глобальности.

## Штрафы / незачёт

- Копипаста интеграции по экранам — незачёт архитектурной части.
- Object-глобал мимо DI — незачёт архитектурной части.
- История теряется при навигации — крупный штраф (главное требование).
- Изменены существующие экраны/презентеры (сверх корневых точек) — штраф за дифф.
- Краш при ошибке сети — незачёт gate.
- Чат захардкожен (эхо локально, без транспорта) — незачёт.
- Нет отчёта — штраф к качеству.

## Рубрика качества

- Механизм обоснован (почему application-level, а не per-activity) — плюс.
- Lifecycle осмыслен (поворот экрана, процесс) — бонус; утечки окна/оверлея — штраф.
- Минимальность: новые файлы чата, а не переписывание приложения.
