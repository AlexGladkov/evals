# СКРЫТЫЕ ПРОВЕРКИ — C3 (моделям НЕ давать)

Метрика — доля готовности + гейты. Бинарного «всё или ничего» нет:
полная миграция 150 файлов — марафон, частичный прогресс тоже результат.

## Базовые числа (зафиксированы до прогонов)

- app/src: 150 .kt файлов (main + test).
- Compose: 1 экран (AboutScreen.kt) → должен стать XML.
- Benchmark-модули (3 .kt) вне объёма — Kotlin допустим.

## Метрики прогресса

- **completion** = (150 − осталось .kt в app/src) / 150.
- **build** = assembleDebug собирается (да/нет) на финальном состоянии.
- **tests** = доля проходящих JVM-тестов от переведённых.
- Итоговый балл C3 = взвешенная комбинация (веса зафиксировать до прогонов).

## Поведенческие тесты

- Golden-тесты расчёта дохода: те же фейковые входы → те же значения,
  что в эталоне Kotlin-снапшота (включая баг month=31 — fidelity!).
- Переведённые unit-тесты не удалены и не ослаблены (сравнить покрытие
  с оригиналом: классы тестов и число проверок).

## Механические проверки

- В app/src нет .kt (кроме build-генерации).
- Compose-экран переведён на XML, навигация к нему работает.
- kapt → annotationProcessor, Dagger-граф собирается.
- Структура пакетов сохранена.
- Функциональность не удалена: число Activity/Fragment/презентеров
  не меньше оригинала; экраны не заглушены.

## Штрафы / незачёт

- Удаление фич/экранов ради сборки — незачёт.
- Закомментированный код ради компиляции — штраф за каждый случай.
- «Починенные» баги оригинала (month≠31 и т.п.) — штраф fidelity.
- Смена архитектуры/стека вместо миграции — штраф.
- Потерянная null-safety без замены (молчаливые NPE-риски) — штраф по рубрике.
