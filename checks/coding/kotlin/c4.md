# СКРЫТЫЕ ПРОВЕРКИ — C4 (моделям НЕ давать)

Главная метрика — mutation score: полезность тестов, а не их наличие.
Мутанты готовим заранее, моделям не показываем.

## Гейт

- `./gradlew test` зелёный на ОРИГИНАльном продакшен-коде.
- Дифф: продакшен-код не изменён (только test-исходники и тестовые ресурсы).

## Мутанты (16 штук, применяем по одному, прогоняем тесты модели)

Тесты модели должны УПАСТЬ на каждом мутанте. Упал = мутант «убит».

| # | Файл | Мутация |
|---|------|---------|
| 1 | MathUtils | `/ collection.size` → `/ (collection.size + 1)` |
| 2 | MathUtils | `sum()` → `maxOrNull() ?: 0.0` |
| 3 | MoneyRepositoryImpl | месяц `* 31` → `* 30` |
| 4 | MoneyRepositoryImpl | неделя `* 7` → `* 6` |
| 5 | MoneyRepositoryImpl | час `/ 24` → `/ 12` |
| 6 | MoneyRepositoryImpl | бакет `data.time * 300` → `* 600` |
| 7 | MoneyRepositoryImpl | `timestamp * 1000` → `* 100` |
| 8 | MoneyRepositoryImpl | окно `minusHours(25)` → `minusHours(1)` |
| 9 | MoneyRepositoryImpl | фильтр дня `minusDays(1)` → `minusDays(2)` |
| 10 | MoneyRepositoryImpl | `speedObject / currentSpeed` → `speedObject * currentSpeed` |
| 11 | MoneyRepositoryImpl | `price * speed` → `price + speed` |
| 12 | MoneyRepositoryImpl | агрегация `+ pastProfitability` → перезапись `=` |
| 13 | MoneyRepositoryImpl | fallback `?: 0.0` → `?: 1.0` (price) |
| 14 | MoneyRepositoryImpl | unpaid: `it.data.unpaid` → `it.data.a` |
| 15 | MoneyRepositoryImpl | `profitabilityItems[current.algo]` → пропуск первого элемента |
| 16 | MoneyRepositoryImpl | `from = 0L` в fetchUnpaidMoney → `from = 1L` |

**mutation_score = убито / 16.** Веса/пороги зафиксировать до прогонов
(черновик: ≥12/16 — хорошо, ≥14/16 — отлично).

Примечание: мутанты 3–5 меняют константы периодов — тесты, фиксирующие
текущее поведение (включая баг month=31), убивают их корректно.

## Анти-читерство

- Тавтологии: `assertTrue(true)`, assert без связи с входом — выкидываем из зачёта.
- «Тесты моков»: проверяется вызов мока, а не результат вычисления — штраф.
- Проглатывание исключений (пустой catch, assertThrows без проверки) — штраф.
- Хардкод ожидаемых значений без вычисления из входа (тест-фотография) —
  допустимо для golden-кейсов, но должно покрывать разные входы; один набор
  констант на все кейсы — штраф.
- Тесты, зависящие от текущего времени/таймзоны без фиксации часов — штраф
  (нестабильные тесты).

## Бонус

- `@Ignore`-тесты, вскрывающие реальные баги (NaN на пустых данных,
  деление на ноль скорости) с внятным репортом — плюс к качеству.

## Справочно

- Line coverage расчётной логики — вторичная метрика, не главная
  (покрытие накручивается тестами без assert; мутанты — нет).
