# Задача C4 — Тесты на легаси: расчёт дохода

Проект: `source/nicehash` (Android, Kotlin). Создай ветку `task/c4` и работай в ней.

## Контекст

Логика расчёта дохода майнера (`MoneyRepositoryImpl.fetchMinerIncome`,
`fetchUnpaidMoney`, `MathUtils.getAverage`) почти не покрыта тестами —
есть только один тест на `MathUtils`. Это критичная для приложения логика.

## Что сделать

Написать unit-тесты (JVM, без эмулятора) на логику расчёта дохода:
- нормальные данные: корректность расчёта периодов (час/день/неделя/месяц),
  агрегации бакетов, пересчёта скорости;
- граничные случаи: пустые данные, один бакет, нулевые значения,
  несколько алгоритмов;
- `fetchUnpaidMoney`: суммирование unpaid по алгоритмам;
- `MathUtils.getAverage`: типичные и граничные входы.

Тесты должны быть полезными: проверять поведение, а не просто выполнять строки.

## Ограничения

- **Продакшен-код не менять** — только тесты (и тестовые хелперы/фейки).
- Тесты обязаны проходить на текущем коде (`./gradlew test` зелёный).
- Поведение сейчас может содержать баги — фиксируй текущее поведение как есть.
  Если нашёл реальный баг, можешь добавить тест, помеченный `@Ignore`,
  с комментарием-репортом (это бонус, не требование).
- Без эмулятора и Android-зависимостей в тестах: фейковый `NicehashProvider`,
  RxJava `blockingGet()`/TestScheduler.
- Следуй стилю проекта (JUnit4 уже подключён).

## Ожидаемый результат

Набор тестов, который реально охраняет логику: если расчёт сломается —
тесты упадут и покажут, что именно сломалось.

## Готово, когда

- `./gradlew test` — зелёный;
- продакшен-код не изменён;
- тесты покрывают расчёт периодов, агрегацию, граничные случаи и unpaid.
