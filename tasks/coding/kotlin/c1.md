# Задача C1 — Фича: экран маркетплейса хешрейта (сеть → UI)

Проект: `source/nicehash` (Android, Kotlin). Создай ветку `task/c1` и работай в ней.

## Контекст

NiceHash отдаёт публичные ордера на покупку хешрейта (метод API `orders.get`).
В приложении этого экрана нет. Добавь его — полностью, от сети до UI,
по существующим паттернам проекта.

## Контракт (фиксирован)

API-ответ (упрощённый `orders.get`):
```json
{"result": {"orders": [
  {"id": "abc123", "algo": 24, "price": 0.12, "speed": 0.5, "alive": true}
]}}
```
- `id` — строка, `algo` — int, `price` — BTC (double), `speed` — TH/s (double),
  `alive` — boolean.

Domain-модель: `HashrateOrder(id: String, algo: Int, price: Double, speed: Double, alive: Boolean)`.
Репозиторий: `MarketRepository.fetchOrders(): Single<List<HashrateOrder>>`.

## Что сделать (вся цепочка, обязательно)

1. **Сеть:** Retrofit-метод в сервисе + API-модель JSON.
2. **Данные:** провайдер (интерфейс + реализация) + конвертер API→domain
   по образцу существующих конвертеров.
3. **Домен:** модель `HashrateOrder` + `MarketRepository` (интерфейс + реализация).
4. **DI:** регистрация во всех нужных модулях (по образцу существующих).
5. **Презентер:** загрузка ордеров, состояния loading / error / empty —
   по образцу `WorkerPresenter`.
6. **UI:** fragment + adapter + layout ячейки + string-ресурсы;
   экран доступен из навигации приложения по существующему паттерну.

## Ограничения

- Следуй стилю и паттернам проекта (MVP + Moxy, Dagger, RxJava2, Retrofit, XML).
- Ошибки сети (HTTP-ошибки, таймаут, битый JSON) → состояние error, не краш.
- Существующие экраны, эндпоинты и тесты не ломать.
- Публичные интерфейсы существующих репозиториев не менять.

## Ожидаемый результат

В навигации появляется экран маркетплейса: список ордеров (алгоритм, цена,
скорость, статус), состояния загрузки/ошибки/пустого списка. Данные приходят
с API по контракту выше.

- `./gradlew test` — зелёный;
- `./gradlew assembleDebug` — собирается;
- вся цепочка на месте (сеть → данные → домен → DI → презентер → UI);
