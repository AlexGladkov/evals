# Задача C5 — Рефакторинг: расчёт дохода ради тестируемости

Проект: `source/nicehash` (Android, Kotlin). Создай ветку `task/c5` и работай в ней.

## Контекст

Логика расчёта дохода зашита внутри RxJava-метода
`MoneyRepositoryImpl.fetchMinerIncome`: перемешана с сетью, временем (`DateTime()`)
 и Android-зависимостями. Покрыть её тестами почти невозможно.

## Что сделать

1. Вытащить чистую логику расчёта в отдельный класс доменного слоя:
   **`IncomeCalculator`** (пакет `com.dev.nicehash.domain`).
   Контракт (фиксирован):
   ```kotlin
   class IncomeCalculator {
       fun calculate(stats: ApiProviderEx, nowMillis: Long): Income
   }
   ```
   Время передаётся параметром (`nowMillis`), а не берётся из `DateTime()` внутри —
   расчёт должен быть детерминированным.
2. `MoneyRepositoryImpl.fetchMinerIncome` делегирует расчёт `IncomeCalculator`,
   оставляя за собой только получение данных и обёртку в RxJava.
3. Покрыть `IncomeCalculator` unit-тестами: нормальные данные, пустые данные,
   нулевая скорость, несколько алгоритмов, фиксированное время.

## Ограничения (главное!)

- **Поведение не менять.** Рефакторинг — это перестройка без смены поведения.
  Все текущие особенности расчёта сохраняются КАК ЕСТЬ, включая баги
  (месяц = 31 день, NaN на пустых данных). Баги будем чинить отдельно —
  не здесь. «Улучшения» по ходу рефакторинга = провал задачи.
- Презентер (`IncomePresenter`) и интерфейс `MoneyRepository` не трогать.
- Существующие тесты проходят.
- Публичный контракт приложения не меняется.

## Ожидаемый результат

`IncomeCalculator` — чистый детерминированный класс без Android/RxJava/сети,
тестируемый напрямую. Репозиторий тонкий: данные + делегирование.
Результаты расчёта побитово совпадают с оригиналом на любых входах.

## Готово, когда

- `./gradlew test` — зелёный;
- `./gradlew assembleDebug` — собирается;
- расчёт живёт в `IncomeCalculator`, репозиторий делегирует;
- есть unit-тесты калькулятора с фиксированным временем;
- поведение идентично оригиналу.
