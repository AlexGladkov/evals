# Задача C3 — Миграция проекта Kotlin → Java

Проект: `source/nicehash` (Android). Создай ветку `task/c3` и работай в ней.

## Цель

Переписать приложение с Kotlin на Java так, чтобы оно собиралось, запускалось
на Android и работало как раньше. Это миграция, а не переизобретение:
архитектура, библиотеки и поведение сохраняются.

## Объём

- Модуль `app` — полностью на Java (сейчас 150 .kt файлов, включая тесты).
- Compose-экраны (например, `AboutScreen.kt`) перевести на XML-view:
  Compose существует только для Kotlin.
- `kapt` заменить на `annotationProcessor` (Dagger, Room).
- Тесты тоже перевести на Java и сохранить их покрытие.
- Benchmark-модули (`macrobenchmark`, `microbenchmark`) можно оставить на Kotlin —
  это измерительная обвязка, её API Kotlin-only.

## Требования

- Сохрани стек и архитектуру: MVP + Moxy, Dagger, RxJava2, Room, Retrofit, XML.
- Сохрани поведение: те же экраны, те же данные, те же расчёты.
  Баги оригинала не чинить — переноси как есть (фиксировать их будем отдельно).
- Сохрани структуру пакетов и именование, адаптированные под Java-conventions.
- Null-safety Kotlin выражай осознанно (аннотации, проверки), а не теряй молча.
- Двигайся модулями/пакетами, держи проект в собираемом состоянии насколько возможно.

## Ограничения

- Не выкидывай функциональность ради сборки (удаление экранов/фич = провал).
- Не меняй публичный контракт приложения (экраны, навигация, API-запросы).
- Не комментируй код ради компиляции.

## Ожидаемый результат

Приложение собирается (`assembleDebug`), устанавливается на Android,
все экраны работают как в оригинале, тесты зелёные.

## Готово, когда

- `./gradlew assembleDebug` — собирается;
- `./gradlew test` — зелёный;
- в `app/src` не осталось .kt файлов (кроме сгенерированного кода);
- поведение сохранено (расчёты дохода совпадают с оригиналом).

Оценивается и частичный прогресс: доля переведённых файлов, собираемость,
проходящие тесты. Дойти до 100% — идеально, но каждый честный шаг учитывается.
